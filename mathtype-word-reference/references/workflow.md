# 已验证的操作流程与注意事项

## 1. 收集输入、建立映射

记录只读参考文档、待修改文档、输出文档。先提取段落和 MathType 对象清单，确认公式实际数学意义。将每个显示公式与正文符号对应到参考对象；主公式的编号和参考编号可以不同。清单中的数学标注由操作者核实，不从 OLE ObjectID 猜含义。

旧 `.doc` 可用单独的后台 Word 实例以只读方式打开，另存临时 `.docx`。务必在 `finally` 中关闭本次打开的文档和实例，不连接并退出用户的现有编辑会话。

## 2. 按用户演示插入新公式

1. 先写 LaTeX 并检查下标、大括号、括号范围、二范数、叉积、最小值约束。
2. 将插入点放到目标公式段落。在 Word 插件中打开 MathType，选择“右编号公式”（不同版本按钮名称可能略有不同）。
3. 在弹出的 MathType 编辑器中粘贴 LaTeX，确认内容被解析为公式结构，而非一串代码；若尚未解析，使用当前 MathType 版本提供的 TeX 输入/转换功能。
4. 核对公式的字体定义和字号与参考相符。标量一般斜体，函数名一般正体，向量/矩阵按文稿约定；已有参考优先遵循参考。
5. 关闭当前 MathType 编辑窗口并接受更新，回到 Word。确认公式居中、编号靠右、可双击编辑，再保存。
6. 正文 `Δs_i`、`κ_max`、`i−1` 等用行内 MathType 对象，不选右编号。字号和基线需与周围文字协调，防止复制时带来“提升字符”效果。

通过当前会话可用的授权 UI/文档接口操作；没有 UI 控制能力时，可复制已有公式对象，或明确说明新增公式缺少实际编辑器操作能力。不得把 OMML、截图或只修改 ProgID 的对象称为 MathType 原生公式。

## 3. 从参考复制相同公式与小符号

使用 `scripts/reference_math.py inspect` 列出对象，再在 `mapping.json` 填入来源段落和对象序号。对显示公式保留全部组成对象；对行内符号逐字串替换，只改该符号。不要为了方便而把参考文档的整段“其中”说明粘贴过来：这样可能复制参考里的错误符号、重复说明、漏掉已有定义或改变权利要求内容。

移植必须同时复制 OLE 二进制和预览图片，重建 relationship，并重新分配关系 ID、shape ID、ObjectID。保持源对象的尺寸和原生流；位置调整需在渲染后判断，不能仅因参考段落的字符提升值存在就盲目沿用到新字号正文。

主公式排版可以复制参考的段落格式和关联样式；对字号、页边距不同的目标文件重新核对制表位。如果对象组与编号重叠，可按目标版心宽度配置居中/右制表位，或通过实际 MathType 插件重建右编号。

## 4. 插入后检查

- 同一公式的字体形状（特别是 a、p、κ）、粗斜体、下标和乘号一致。
- 正文同名符号与主公式一致；只剩技术缩写如 ADAS/PCD 时不必把它们当数学符号。
- 主公式始终以完整数学关系为单位编号；正文符号无编号。
- 所有关系和嵌入对象可解析，原生流不是 XML 字符串伪装。
- 含多个 OLE 的显示公式保持整体，清点“公式段落”和“对象数”两个指标。
- 逐页检查 PDF/截图；缓存中出现字节 `?` 不一定是可见问号，出现字节警告必须目视确认，不能直接说通过或直接删除公式。
- 关闭本任务后台对象并释放文档句柄，保留可编辑 Word 成品与必要的审计记录。

## 5. 复用边界

参考移植流程已经用于主公式及行内符号，原生字体可通过复制得到保留。不同版本 MathType、WPS、Word 对编号域和基线可能有差异，因此新的环境仍需做一次代表性公式验证。脚本的离线审计可以验证存储与关系，无法自行证明全部公式语义或实际双击后的逐项编辑行为。
